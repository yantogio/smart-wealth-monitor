## ADDED Requirements

### Requirement: Project README
The repository README SHALL describe this application rather than the Laravel framework, and SHALL contain: a one-sentence statement of what the application does, screenshots of the running interface, a feature list, an architecture overview, setup instructions, and a link to the OpenSpec specifications.

#### Scenario: Reader identifies the project
- **WHEN** a visitor reads the first screen of the README
- **THEN** they learn that the application tracks IDX stock and gold prices, flags discount opportunities, and simulates DCA — without needing to open any source file

#### Scenario: No stock framework content remains
- **WHEN** the README is inspected
- **THEN** it contains no Laravel marketing copy, Laravel logo, or links to Laravel documentation presented as project documentation

#### Scenario: Design process is visible
- **WHEN** a visitor wants to understand how the project was designed
- **THEN** the README points them to the OpenSpec capability specifications and explains what they represent

### Requirement: Zero-Friction Setup Path
The README SHALL document a setup path that takes a fresh clone to a populated, browsable application using no database server, no API key, and no network access beyond installing dependencies.

#### Scenario: Newcomer runs the documented commands
- **WHEN** a user follows the README setup steps exactly on a clean clone
- **THEN** the application starts and the dashboard shows populated prices for every asset

#### Scenario: Default database requires no server
- **WHEN** a user sets up the project using the shipped environment example
- **THEN** the application uses a file-based SQLite database created by the setup steps, with no separate database server to install or configure

#### Scenario: Production database documented
- **WHEN** a user wants to run the application against MySQL instead
- **THEN** the README documents the required environment changes

#### Scenario: Live sync documented separately
- **WHEN** a user wants real current prices rather than demo data
- **THEN** the README explains how to obtain and configure an API key and how to run the sync, clearly marked as optional and distinct from the demo path

### Requirement: Interface Screenshots
The repository SHALL include committed screenshots of the dashboard, the watchlist with its price chart, and a completed DCA simulation, displayed in the README.

#### Scenario: Visitor evaluates without cloning
- **WHEN** a visitor views the README on GitHub
- **THEN** they can see what each main screen of the application looks like with real data in it

### Requirement: Stated Deployment Limitation
The README SHALL state that the application has no authentication and is intended as a local, single-user tool that should not be exposed publicly without adding access control.

#### Scenario: Reader considers deploying
- **WHEN** a visitor reads the README with the intent to deploy the application
- **THEN** they are warned that the settings page, including API key management and sync triggering, is unauthenticated

### Requirement: Open Source License
The repository SHALL include a LICENSE file granting clear terms for reuse.

#### Scenario: Visitor checks licensing
- **WHEN** a visitor opens the repository
- **THEN** a LICENSE file is present at the root and GitHub displays the license name

### Requirement: Repository Free Of Scaffolding
The repository SHALL NOT contain unused files generated by the framework installer that serve no purpose in this application.

#### Scenario: Reviewer browses the codebase
- **WHEN** a reviewer inspects the test suite and view directory
- **THEN** no placeholder example tests or unused default landing views remain, and every test present exercises application behavior
